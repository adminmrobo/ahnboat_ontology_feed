# ahnboat lab 온톨로지 피드

ahnboat.xyz 공개 콘텐츠의 **최신 온톨로지(개념·정의·관계)를 분야별 RSS**로 내보내고, 그 피드를 근거로 생성 AI에게 **내 아이디어를 검증해 달라고 요청하는 지시문**을 만들어 주는 저장소입니다.

- 연구실 도구함: https://adminmrobo.github.io/ahnboat_ontology_feed/ (아이디어 검증 `check/` · 결과물 평가 `review/`)
- AI 도구용 안내: https://adminmrobo.github.io/ahnboat_ontology_feed/llms.txt

## 왜 RSS인가

질문마다 답을 돌려주는 API와 달리, 여기서 필요한 것은 **지금 이 분야의 최신 온톨로지 한 벌**입니다. 그래서 서버 없이 GitHub Pages에 정적 파일로 두고, 원본이 바뀔 때마다 최신판으로 덮어씁니다. 사용자는 뉴스 주제를 고르듯 분야를 하나 이상 고르거나 전체를 고릅니다.

## 연구실 도구함 구조

| 주소 | 내용 |
|---|---|
| `/` (`index.html`) | 연구실 도구함 첫 화면 — 도구 목록 |
| `/check/` | 아이디어 검증하기 |
| `/review/` | 결과물 평가하기 |
| `assets/labkit.js` · `labkit.css` | 모든 도구가 함께 쓰는 코드: 위쪽 메뉴, 캐릭터 움직임, 관련 개념 찾기, 링크 대조 |
| `rubrics/` | 결과물 평가 기준표(JSON) |

**새 도구 붙이기**: ① `<도구>/index.html`을 만들고 `../assets/labkit.css`·`../assets/labkit.js`를 불러 `LabKit.nav(…, "<도구 id>", "../")`를 부릅니다. ② `assets/labkit.js`의 `TOOLS`에 한 줄을 더하면 모든 페이지 메뉴와 첫 화면 목록에 나타납니다.

## 결과물 평가하기 (`review/`)

연구실 스킬 형식(흰 배경, 처음 오신 분께 3줄, 등장인물, 튜토리얼, AI 판단 코너, 마무리)을 서비스 화면에 맞췄습니다. 하루(안내)·시아(기준표)·모아(근거 기록)가 튜토리얼 6단계로 안내하고, 주판봇은 점수 계산, 초파리 연구원은 반대 심사위원을 맡습니다. 박사는 도구함까지 만드느라 또 자는 중입니다.

- **① 종류 고르기**: 아이디어 · 논문 · 제안서 · 사내 개선안 · 강의안 · 도안
- **② 기준표 다듬기**: 항목별 가중치(고칠 수 있음, 합이 100이 아니면 비율로 맞춤), 1·3·5점의 뜻, 심사위원 관점 3개 + 반대 심사위원(늘 포함)
- **③ 문서 정보**: 제목·제출처·요약(선택). 요약에서 관련 개념을 찾아 지시문에 근거로 넣고, 찾은 개념이 많은 분야 두 곳의 텍스트판 피드를 붙입니다.
- **④ 지시문**: 점수마다 문서 속 근거 위치를 요구하고, 근거가 없으면 '판단 불가'. 점수표는 정해진 표 모양으로 받습니다.
- **⑤ 점수 확인 도우미**: AI 답을 붙여 넣으면 점수표를 읽어 가중 총점을 다시 계산하고(판단 불가 제외), AI가 적은 총점과 비교하고, 근거 위치 없는 점수·빠진 항목·전부 4점 이상인 몰아주기를 표시하고, 가장 먼저 고칠 항목을 짚습니다. 연구실 링크가 있으면 개념 지도와 대조합니다.
- **기준표 파일**(`rubrics/<종류>.json`): `criteria`마다 `name`·`weight`(합 100)·`check`(확인할 것)·`a1`/`a3`/`a5`(점수의 뜻), `judges`(심사위원 관점), `notes`. 종류를 늘리려면 파일을 하나 더하고 `rubrics/index.json`에 한 줄 추가합니다. 강의안은 연구실 원리 먼저 교수법(P1~P7)을 그대로 씁니다.

## 아이디어 검증하기 (`check/`)

연구실 스킬(ai-lab-explainer-plain)의 형식을 서비스 화면에 맞춰 옮겼습니다.

- 히어로 무대: 하루·시아·모아가 안내하고, 주판봇과 초파리 연구원은 만족해하고, 미공개 X1·X2·X3은 방청석에서 박수를 칩니다. 박사는 이걸 만드느라 밤을 새워 자는 중입니다.
- 처음 오신 분께 3줄 요약과 처음 보는 말 풀이
- 튜토리얼 5단계: 시작(하루) → 분야 고르기(시아) → 아이디어 쓰기(모아) → 복사해서 붙이기(하루) → 답 확인하기(시아). 단계마다 해당 도구로 이동해 강조 표시
- 도구: 분야 고르기 → 아이디어 쓰기 → 지시문 복사 → 답 확인하기
  - **관련 개념 미리 찾기**: 아이디어 글의 낱말로 개념 지도(`feeds/search.json`)를 찾아, 고른 분야에서 12개·고르지 않은 분야에서 6개까지 보여 주고 체크한 것을 지시문에 직접 넣습니다. AI가 피드 링크를 못 읽어도 근거가 전달됩니다. 낱말은 개념 이름에 드물게 나올수록 무겁게 셉니다. 위쪽에서 찾은 개념 8개의 온톨로지 관계를 따라 **관계로 이어진 개념**(개념 하나당 둘까지, '관련' 관계 먼저)도 보여 주므로, 아이디어에 쓰지 않은 낱말의 개념도 찾습니다. 두 개념 이상에서 이어진 것만 미리 체크합니다.
  - **답 형식**: 길이(핵심만·보통·보고서), 수식은 일반 글자로, 온톨로지에 없는 개념 제안 받기
  - **답 확인 도우미**: AI 답을 붙여 넣으면 연구실 링크를 개념 지도와 대조해 있음 / 위치 확인 필요 / 없는 주소로 판정하고, [피드]·[일반 지식] 표시 수를 셉니다. 추적 꼬리표(`?utm_source=…`)는 떼고 확인합니다. 글은 브라우저 밖으로 보내지 않습니다.
- AI 판단 코너: 지어낸 출처가 섞인 답에서 수상한 줄 찾기(초파리 연구원)
- 시연: 같은 아이디어를 지시문만으로 / 피드와 함께 물었을 때 비교
- 피드 주소 표, 마무리 대화
- 그림은 연구실 캐릭터 팩(lab4, `ahnboat_lab_explainer/packs/character`)의 표정·동작 그림을 `assets/char/`에 복사해 씁니다.
- 배경·표지 그림 Genspark 요청문: [`docs/GENSPARK_cover.md`](docs/GENSPARK_cover.md) (G1 무대 배경 `bg_hero` · G2 배너 배경 `bg_banner` · G3 표지 `cover`). PNG를 `assets/`에 올리면 자동 갱신 작업이 WebP로 바꾸고 페이지·배너가 배경으로 씁니다.
- 서비스 페이지라서 해설 페이지의 지식 색인(#kg)·꾸러미(#export)는 넣지 않았습니다. 이 페이지가 공개 카탈로그에 오르면 피드가 자기 자신을 개념으로 다시 담게 되기 때문입니다.

## 홈페이지 바로가기 배너 (`banner.html`)

ahnboat.xyz에 끼워 넣는 '연구실 도구함' 배너입니다. 홈페이지의 헤드·배웅 배너와 같은 점무늬 종이·검은 테두리·그림자 모양이고, 누르면 연구실 도구함이 새 탭으로 열립니다.

- 배너 주소: https://adminmrobo.github.io/ahnboat_ontology_feed/banner.html
- 워드프레스에 붙이기: [`docs/wp_banner_block.html`](docs/wp_banner_block.html)의 내용을 '사용자 정의 HTML' 블록에 그대로 붙여 넣습니다. 높이는 배너가 알려 주는 값(`ahnboat-catalog-height`)으로 저절로 맞춰집니다.
- 언어: 홈페이지에서 고른 언어(`ahnboat-lang`)를 따라 7개 언어(ko·en·zh·ja·uz·ru·vi)로 바뀝니다. 지시문 생성 페이지는 한국어라 외국어 배너의 버튼에는 "(한국어 페이지)"라고 적었습니다.
- 숫자(분야·개념 수)는 `feeds/index.json`에서 읽어 늘 최신입니다. `bg_banner` 그림이 있으면 배경으로 깝니다.

## 만들어지는 파일

| 파일 | 내용 |
|---|---|
| `feeds/<분야>.xml` | 분야 하나의 피드(RSS 리더 구독용 전체). 콘텐츠(해설 시리즈)마다 항목 하나, 설명에 페이지 목록(`p1 = 제목 — 주소`)·개념(유형·정의·`[p1#위치]`)·관계. 같은 피드 안에서 이미 나온 개념은 이름만 다시 적음 |
| `feeds/<분야>-p1.xml`, `-p2.xml` | 생성 AI용 나눔 파일. 생성 AI의 웹 읽기 도구는 한 번에 약 10만 자까지만 읽는 경우가 많아, 9만 자를 넘는 분야는 나눠서 함께 만든다. 지시문에는 이 파일이 들어간다 |
| `feeds/txt/*.txt` | 위 피드와 같은 내용의 일반 텍스트판. XML을 못 읽는 AI 웹 도구용이며 지시문에는 이 주소가 들어간다 |
| `feeds/search.json` | 관련 개념 미리 찾기·답 확인 도우미용 색인(개념 이름·영문·유형·정의·출처·관계로 이어진 이웃, 페이지별 위치 목록) |
| `feeds/all.xml` (+ `all-p1/p2.xml`) | 전체 분야 요약 피드. 개념 이름만 담아 가볍게 |
| `ontology/<분야>.jsonld` | 분야 하나의 전체 온톨로지(SKOS 기반 JSON-LD). 기계가 읽는 용도 |
| `feeds/index.json` | 분야 목록·통계. 지시문 생성 페이지가 읽음 |
| `llms.txt` | 생성 AI가 이 사이트를 읽는 법 |
| `config/field_slugs.json` | 분야 이름 → 피드 파일 이름. **한번 정한 이름은 바꾸지 않습니다**(피드 주소 고정). 분야 이름이 바뀌면 새 줄이 생기며, 예전 주소를 살리려면 새 이름에 예전 파일 이름을 손으로 적어 줍니다 |

분야는 서버실 랙(대분류)과 같습니다: 머신러닝, 딥러닝·뇌과학, AI 감각·생성, LLM·추론 엔지니어링, 경제·수학·최적화, 금융·핀테크·블록체인, 통계·데이터 기초, 인공지능 응용.

## 데이터 흐름

```
각 해설 저장소의 #kg(지식 색인)
   → ahnboat_lab_cover_status  scripts/build_ontology.py  → data/ontology.json   (하루 두 번)
   → 이 저장소                 scripts/build_feeds.py     → feeds/ · ontology/ · llms.txt (하루 두 번)
```

온톨로지를 새로 모으지 않고, cover_status가 이미 만든 `data/ontology.json`(공개 카탈로그에 있는 콘텐츠만)을 받아 형식만 바꿉니다. 그래서 공개 범위와 분류는 cover_status의 관리실 설정을 그대로 따릅니다.

## 자동 갱신

`.github/workflows/build.yml`이 하루 두 번(한국 시간 08:43·20:43 예약, GitHub 사정으로 밀릴 수 있음)과 Actions 탭의 수동 실행 때 피드를 다시 만들고, 바뀐 것이 있으면 커밋합니다.

## GitHub Pages 켜기

Settings → Pages → Build and deployment → Source: **Deploy from a branch** → Branch: **main** / **(root)** → Save.

## 로컬에서 만들기

```bash
python3 scripts/build_feeds.py                          # GitHub에서 원본을 받아 만든다
python3 scripts/build_feeds.py --src ../ahnboat_lab_cover_status   # 로컬 사본으로 만든다
python3 -m http.server 8000                             # http://localhost:8000/
```

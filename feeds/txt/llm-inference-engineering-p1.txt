- 키워드 검색 (방법) — 질문과 같은 글자의 단어가 많은 문장을 고르는 검색. [p1#lv2]
- 뜻으로 찾기 (임베딩 검색) (방법) — 문장을 뜻 벡터로 바꾸고 코사인 유사도가 높은 문장을 고르는 검색. [p1#lv3]
- 조각 + 상위 k개 검색 (방법) — 문서를 조각으로 자르고 점수 상위 k개 조각을 가져오는 검색. [p1#lv4]

- 벡터의 길이 (L2 노름) (용어) — 숫자를 제곱해 더한 뒤 제곱근을 씌운 값. 피타고라스 정리와 같다. [p1#lv3]
- 벡터 DB (개념) — 조각과 그 숫자 줄을 모아 두고 비슷한 것을 빨리 찾는 저장소. [p1#big]
- 청크 (조각) (개념) — 긴 문서를 검색하기 좋게 자른 한 조각. [p1#lv4]
- 조각 겹침 (용어) — 앞 조각과 겹치게 자르는 문장(글자) 수. [p1#lv4]
- 상위 k개 (top-k) (용어) — 점수가 높은 순서로 k개만 가져오기. [p1#lv4]
- 프롬프트 (개념) — LLM에 건네는 지시문. 여기서는 지시 + 조각 + 질문. [p1#lv5]

- 준비 단계 (색인) (개념) — 문서 읽기·자르기·임베딩·서가에 꽂기를 미리 한 번 하는 단계. [p1#big]
- 질문 단계 (개념) — 질문을 숫자로 바꾸고 찾은 조각과 함께 LLM에 건네는 단계. [p1#big]
- 다음 말 확률 (개념) — 앞 문장이 주어졌을 때 다음에 올 말의 조건부 확률. [p1#lv1]

- 지도 미세조정 (SFT) (방법) — 문의와 정답 양식 짝으로 손실을 줄이도록 모델의 무게를 고치는 방법. [p2#lv2]
- 학습률과 에포크 (개념) — 한 번에 고치는 세기(학습률)와 학습 기록 전체를 도는 바퀴 수(에포크). [p2#lv3]
- 미세조정 (개념) — 이미 학습된 바탕 모델에 새 기록을 더 가르쳐 무게를 고치는 일. [p2#why]
- 바탕 모델 (개념) — 미세조정하기 전의 원래 모델. [p2#big]
- 맥락 속 학습 (개념) — 무게를 바꾸지 않고 프롬프트 안 예시만 보고 형식을 따라 하는 성질. [p2#lv1]
- 바탕 모델의 버릇 (개념) — 예시를 붙여도 남는 바탕 모델의 원래 경향. 이 페이지에서는 버릇 점수로 흉내 냈다. [p2#lv1]
- 무게 고치기 한 걸음 (용어) — w ← w − η × (p − y) × x. 틀린 만큼, 그 주제 숫자만큼 고친다. [p2#lv2]

- 호출당 글자 수 (지표) — 질문 하나에 모델로 보내는 글자 수. 비용·속도와 비례한다. [p2#lv1]

- 글자 채점 (EM·F1) (지표) — 정답 문장과 글자가 똑같은지(EM), 낱말이 얼마나 겹치는지(F1)로 매기는 채점. [p3#lv1]
- 블라인드 쌍대 비교 (방법) — 누구 답인지 가리고 두 답 중 나은 쪽을 사람이 고르게 하는 평가. [p3#lv2]

- 답 정리 (소문자·구두점·관사 지우기) (용어) — 비교 전에 대소문자·구두점·a/an/the를 지우는 일. [p3#lv1]

- ReAct 고리 (생각·행동·관찰) (방법) — 생각 → 도구 행동 → 관찰을 되풀이하다 끝나면 답하는 에이전트 방식. [p4#lv2]

- 모델 붕괴 (개념) — 모델이 만든 데이터를 가리지 않고 다시 학습에 쓰면 원래 분포의 꼬리가 사라지는 결함 [p1#s4]

- 개선 대상 × 순환이 닫힌 정도 (개념) — 무엇을 고치나(행동·가중치·평가자·연구 과정)와 사람이 순환 어디에 있나로 RSI 연구를 나누는 틀 [p1#s3]
- 괴델 머신 (방법) — 수정이 유용하다는 증명을 찾으면 자기 코드를 고쳐 쓰는 이론 모델 [p1#s2]
- 다윈 괴델 머신 (DGM) (방법) — 증명 대신 벤치마크 실험 증거로 수정을 받아들이고, 만든 에이전트를 보관소에 모두 남기는 자기개선 코딩 에이전트 [p1#s2]
- 보관소 탐색 (방법) — 점수가 낮아도 새로운 시도를 남겨 다음 탐색의 출발점으로 쓰는 방법 [p1#s2]

- Self-Rewarding LM (방법) — 모델이 스스로 채점하며 반복 학습해 지시 수행과 채점 능력을 함께 키움 [p1#s4]
- GUARD · Soft-HURT 관문 (방법) — 가중치를 고정하고 하네스만 고치며, 얻는 것이 잃는 것보다 여유만큼 클 때만 수정을 받아들이는 관문 [p1#s5]
- 사전학습의 작은 순환들 (801) (방법) — 다시 돌릴 수 없는 사전학습을 디버깅·헤드룸·경험을 지표로 바꾸는 작은 순환들로 나눠 개선 [p1#s3]

- 피드백 깔때기 p^k (개념) — 단계마다 남는 비율 p를 클릭 수 k번 곱한 만큼만 피드백이 남는다 [p2#s2]
- 개선 담당 에이전트 (개념) — 정해진 때마다 제안한 것과 실제 응답을 견주어 규칙 파일의 작고 초점 있는 수정 하나를 초안으로 내는 두 번째 에이전트 [p2#s3]
- 한 번에 수정 하나 (방법) — 여러 규칙을 함께 바꾸지 않고 한 번에 하나만 바꿔 원인 추적과 되돌리기를 쉽게 하는 방법 [p2#s3]
- 반씩 나눠 되돌리기 (방법) — 여러 수정 중 원인을 찾을 때 절반씩 되돌려 보는 방법. 최악 log₂(수정 수)번 확인 [p2#s3]
- 정답 예시 묶음 (골든 아웃풋) (개념) — "이렇게 나오면 맞다"를 수정보다 먼저 정해 둔 예시 모음. 수정 전후 통과율을 재는 자 [p2#s5]

- 채팅 템플릿 (용어) — 역할이 있는 대화, 도구 설명 등을 한 줄 입력으로 합치는 형식. 모델마다 조금씩 다르다. [p8#lv3]
- 문맥 창 (용어) — 한 요청에서 처리·생성할 수 있는 토큰 총수. [p8#lv3]
- 인과 마스크 (용어) — 뒤에 오는 토큰을 보지 못하게 가리는 장치. [p8#lv4]
- 크로스 어텐션 (방법) — Q가 K·V와 다른 열에서 오는 어텐션. 이미지 생성·멀티모달 모델이 쓴다. [p8#lv4]
- 피드포워드 층 (개념) — 트랜스포머 블록 안의 다층 퍼셉트론. 학습 가능한 가중치의 대부분을 차지한다. [p8#summary]
- LM 헤드 (용어) — 은닉 상태를 어휘 크기의 로짓 벡터로 바꾸는 출력층. [p8#summary]
- 임베딩층 (용어) — 토큰을 받아 임베딩을 돌려주는 입력층. [p8#summary]
- 라우터 (용어) — 층마다 어떤 전문가를 쓸지 고르는 LLM 안의 작은 모델. [p8#lv5]
- 전문가 병렬화 (방법) — 전문가를 여러 GPU에 나눠 싣는 추론 병렬화. 대규모 배치에서 희소성을 살린다. [p8#lv5]
- 인과 언어 모델 (개념) — 앞 토큰만 보고 다음 토큰을 예측하는 언어 모델. 오늘날 생성 LLM 전부. [p8#lv5]
- config.json (용어) — Hugging Face 모델마다 있는, 아키텍처와 층 크기를 적은 수십 줄 파일. [p8#summary]
- 자기회귀 토큰 생성 (방법) — 토큰 열에서 다음 토큰을 하나씩 예측해 이어 붙이는 생성 방식. [p8#big]
- 반복 노이즈 제거 (방법) — 무작위 노이즈에서 출발해 확산으로 결과를 다듬는 생성 방식. [p8#big]
- 배치 기준 활성 계획 (방법) — 배치 서버에서는 거의 모든 전문가가 켜진다고 보고 메모리·계산을 계획한다 (초파리 연구원의 선택). [p8#duel]
- 이름표 기준 활성 계획 (방법) — 토큰당 고르는 비율(8/128)만큼만 일한다고 보고 계획한다 (주판봇의 선택). [p8#duel]
- 켜진 전문가 비율 (지표) — 한 디코드 단계에서 한 번이라도 선택된 전문가의 비율. [p8#lv5]
- 예측 오차 (지표) — 예측한 켜진 비율과 측정한 비율의 차이(%p). 작을수록 좋다. [p8#duel]
- 발화 문턱 (생물 대응) — 뉴런은 입력이 문턱을 넘어야 발화한다. ReLU의 꺾임과 닮았다(실제 뉴런은 스파이크를 낸다). [p8#lv2]
- 표준 어텐션 (방법) — S=QKᵀ, P=softmax(S)를 창고 메모리에 쓰고 다시 읽어 O=PV를 계산하는 구현(알고리즘 0). [p10#q]
- 블록 희소 번개 어텐션 (방법) — 마스크가 0인 블록을 건너뛰는 근사 어텐션. 창고 접근이 희소도 s에 비례해 준다. [p10#reread]
- 근사 어텐션 (방법) — 희소·저랭크 근사로 계산을 줄인 어텐션. 실행 시간이 줄지 않는 경우가 많았다. [p10#q]
- 쟁반 나누기 (타일링) (방법) — 입력을 빠른 메모리에 들어가는 블록으로 나눠 여러 번에 걸쳐 처리하는 기법. [p10#method]
- 다시 계산하기 (재계산) (방법) — 순방향의 N×N 중간값을 보관하지 않고 역방향에서 다시 계산하는 기법. [p10#lab]
- 한 번에 몰아 하기 (커널 융합) (방법) — 여러 연산을 GPU 커널 하나로 묶어 입력을 한 번만 읽게 하는 기법. [p10#lab]
- 온라인 소프트맥스 (방법) — 최댓값 m과 지수합 ℓ을 들고 다니며 블록별 소프트맥스를 정확히 합치는 방법. [p10#r2]
- 그래디언트 체크포인팅 (방법) — 중간값 일부만 보관하고 역방향에서 다시 계산해 메모리를 아끼는 방법. [p10#lab]
- IO-인지 (개념) — 빠른 메모리와 느린 메모리 사이의 읽기·쓰기 양을 따져 알고리즘을 설계하는 원칙. [p10#q]
- 메모리 계층 (개념) — 작고 빠른 메모리부터 크고 느린 메모리까지 층을 이룬 구조 (SRAM, HBM, DRAM). [p10#q]
- 실험대 메모리 (SRAM) (개념) — GPU 칩 위 작은 메모리. A100 SM당 192KB, 약 19TB/s. [p10#q]
- 메모리 바운드 (개념) — 계산보다 메모리 접근이 시간을 정하는 연산. [p10#q]
- 계산 바운드 (개념) — 산술 연산 횟수가 시간을 정하는 연산(큰 행렬 곱 등). [p10#q]
- 산술 강도 (개념) — 메모리 1바이트당 산술 연산 수. [p10#reread]
- IO 복잡도 (개념) — 알고리즘이 느린 메모리에 접근하는 횟수를 입력 크기의 함수로 나타낸 것. [p10#r1]
- 어텐션 행렬 (개념) — N×N 점수 행렬 S=QKᵀ와 그 소프트맥스 P. [p10#q]
- 정확한 어텐션 (개념) — 근사 없이 softmax(QKᵀ)V와 같은 값을 내는 계산. [p10#r2]
- 실행 시간 (지표) — 실제 시계로 잰 시간(ms). [p10#r1]
- 창고 왕복량 (지표) — 창고 메모리에서 읽고 쓴 양(GB 또는 원소 수). [p10#r1]
- 메모리 사용량 (지표) — 계산에 필요한 최대 GPU 메모리. [p10#r3]
- Path-X / Path-256 (데이터) — 흑백 그림의 두 점이 이어졌는지 한 픽셀씩 읽어 맞히는 긴 문맥 과제(16K, 64K). [p10#r3]
- Long-range Arena (데이터) — 긴 문맥 트랜스포머를 비교하는 벤치마크 (길이 1K~4K 다섯 과제). [p10#r3]
- 이미지 생성 파이프라인 (방법) — 텍스트 인코더·디노이저·VAE가 이어진 여러 모델의 파이프라인. [p12#lv2]
- 텍스트 인코더 (방법) — 텍스트 프롬프트를 이미지 생성 모델이 이해하는 지시로 바꾸는 부품. [p12#lv2]
- VAE(변분 오토인코더) (방법) — 잠재 공간의 출력을 픽셀 공간으로 바꾸는 부품. [p12#lv2]
- 가이던스 스케일 (개념) — 조건 있는/없는 두 순전파 결과를 섞는 비율. 창의성과 프롬프트 충실도의 균형, 보통 4 안팎의 정수. [p12#lv3]
- 네거티브 프롬프트 (개념) — 이미지에 없어야 할 화풍·물체를 따로 적는 인자. [p12#lv3]
- LoRA (방법) — 화풍을 바꾸고 품질을 올리는 가벼운 파인튜닝. [p12#lv2]
- ControlNet (방법) — 윤곽·외곽선으로 출력의 큰 모양과 색을 이끄는 부품. [p12#lv2]
- 확산 트랜스포머 (방법) — 토큰 임베딩 대신 이미지 데이터(패치)를 처리하는 트랜스포머. [p12#lv2]
- SDXL (방법) — 베이스와 리파이너 두 디노이저를 가진 파이프라인의 깔끔한 예(2023). [p12#lv2]
- Qwen Image (방법) — Qwen 2.5 VL(7B) 텍스트 인코더, 20B 디노이저, 이중 인코딩 VAE(2025). [p12#lv2]
- 퓨스텝 모델 (방법) — 8단계 이하로 고해상도 이미지를 만드는 모델. 80–90% 빠르지만 품질이 낮다. [p12#lv4]
- 잠재 일관성 (방법) — 목표 잠재 벡터를 직접 예측하고 2–4번 반복해 품질을 올리는 방법. [p12#lv4]
- 영상 생성 모델 (방법) — X·Y·T 잠재 공간에 영상 전체를 두고 함께 디노이징하는 모델. [p12#lv5]
- 오차 누적 (개념) — 프레임을 하나씩 이어 만들 때 앞의 작은 오류가 뒤로 번지는 현상. [p12#lv5]
- Self Forcing (방법) — 품질의 전체 시야와 반복 생성을 결합하는 영상 생성 기법. [p12#lv5]
- 메모리 대역폭 (개념) — GPU가 초당 옮길 수 있는 바이트 수. [p12#lv1]
- ops:byte 비율 (개념) — GPU의 연산 성능 ÷ 메모리 대역폭. H100 FP16은 약 295. [p12#lv6]
- 루프라인 모델 (방법) — 대역폭 한도(대각선)와 성능 한도(수평선)에 산술 강도를 놓아 병목을 보는 그래프. [p12#lv6]
- KV 캐시 (개념) — 앞 토큰들의 키·값 계산 결과를 저장해 디코드 어텐션을 선형 시간으로 만드는 저장소. [p12#lv8]
- 어텐션 (개념) — 가장 비싼 추론 연산. 입력 길이의 제곱으로 늘어난다. [p12#lv7]
- FP16 (용어) — 값 하나가 2바이트인 16비트 부동소수점 형식. [p12#lv1]
- 슬라이딩 윈도우 어텐션 (방법) — 직전 w개 토큰만 봐서 O(N²)을 O(Nw)로. w는 흔히 8K–32K. [p12#lv9]
- 게이트 어텐션 (방법) — 훈련 때 넣은 층으로 일부 구간의 어텐션을 선형 시간으로 근사. [p12#lv9]
- 선형 어텐션 (방법) — 제곱인 소프트맥스 식을 선형 시간 근사로 바꿈. [p12#lv9]
- 압축 어텐션 (방법) — 앞쪽 문맥을 주기적으로 압축해 최근 토큰과 함께 봄. [p12#lv9]
- 멀티 잠재 어텐션 (방법) — 저차원 잠재 공간에서 어텐션을 근사. [p12#lv9]
- 맘바 (방법) — 셀프 어텐션 대신 순환 상태 갱신으로 길이에 선형인 선택적 상태 공간 모델. [p12#lv9]
- 하이브리드 모델 (방법) — 맘바식 상태 공간 블록과 트랜스포머 블록을 섞은 모델. [p12#lv9]
- 루프라인 모형 (방법) — 성능 상한 = min(최대 계산력, 대역폭 × 작업 강도)를 로그-로그 그림으로. [p13#method]
- 작업 강도 (지표) — DRAM 1바이트당 연산 수. [p13#method]
- 능선점 (개념) — 최대 성능에 필요한 최소 작업 강도. [p13#r1]
- 천장 (개념) — 특정 최적화를 하기 전에는 넘을 수 없는, 지붕 아래의 가로선(계산) 또는 비스듬한 선(메모리). [p13#r2]
- 한계·병목 분석 (개념) — 성능을 예측하는 대신 무엇이 성능을 막는지(한계)를 드러내는 분석. 암달의 법칙이 대표 예. [p13#q]
- 3C 캐시 미스 (개념) — 캐시 미스의 세 종류(필수 · 용량 · 충돌). 필수 미스가 작업 강도의 최대치를 정한다. [p13#r4]
- ILP · SIMD (방법) — 최적화 ①: 명령어 수준 병렬성을 높이고(루프 펼치기) SIMD 명령을 쓴다. [p13#r2]
- 곱셈·덧셈 균형 (방법) — 최적화 ②: 부동소수점 곱셈과 덧셈 수를 맞춰 곱셈-덧셈 장치를 다 쓴다. [p13#r2]
- 단위 보폭 접근 (방법) — 최적화 ③: 메모리를 연속으로 읽게 루프를 바꿔 하드웨어 프리페치를 켠다. [p13#r2]
- 메모리 친화성 (방법) — 최적화 ④: 데이터와 그 데이터를 쓰는 스레드를 같은 칩-메모리 쌍에 둔다. [p13#r2]
- 소프트웨어 프리페치 (방법) — 최적화 ⑤: 소프트웨어로 메모리 요청을 미리 많이 띄워 지연시간을 숨긴다. [p13#r2]
- 멀티코어 넷 (Xeon · X4 · T2+ · Cell) (데이터) — 2소켓 멀티코어 넷: Intel Xeon, AMD Opteron X4, Sun UltraSPARC T2+, IBM Cell (표 1). [p13#r3]
- 가속기 (개념) — 대량 데이터를 싣고 초당 수조 번 계산하도록 만든 하드웨어. [p14#top]
- GPU 세 종류 (데이터센터 · 워크스테이션 · 개인) (개념) — 데이터센터(예: B200) · 워크스테이션(예: RTX Pro 6000) · 개인용(예: RTX 5090) GPU. [p14#lv1]
- 클라우드 · 온프레미스 · 에어갭 (개념) — 데이터센터 GPU를 쓰는 세 자리: 빌리기(클라우드) · 사서 직접 통제(온프레미스) · 외부망 차단(에어갭). [p14#lv1]
- SM (계산 공방) (개념) — GPU 안의 작업장. SM마다 여러 코어(CUDA · 텐서 · SFU)와 L1 캐시가 있다. [p14#lv2]
- 텐서 코어 (개념) — 행렬·벡터 연산 코어. MMA 담당. [p14#lv2]
- MMA (D = A×B + C) (개념) — D = (A × B) + C. 곱한 결과를 바탕 행렬에 더하는 텐서 코어의 기본 동작(그림 3.1). [p14#lv2]
- VRAM (HBM) (개념) — GPU에 붙은 큰 메모리(DRAM, HBM 형태). 모델 무게와 KV 캐시를 담는다. [p14#lv3]
- 캐시 L0 · L1 · L2 (SRAM) (개념) — 칩 안 SRAM 캐시. L0(텐서 코어 명령) · L1(SM마다, H100 256 KB) · L2(공유, H100 50 MB). [p14#lv3]
- 메모리 대역폭 (지표) — VRAM에서 GPU 코어 쪽으로 1초에 옮길 수 있는 최대량. 디코드 속도의 상한을 정한다. [p14#lv3]
- VRAM = 무게 + 50% 여유 (개념) — 필요 VRAM ≈ 모델 무게 + 최소 50% 여유(KV 캐시). 긴 문맥 · 큰 배치 · 영상 모델은 더. [p14#lv3]
- 프리필 · 이미지 · 영상 = 계산 병목 (개념) — LLM 프리필, 이미지 · 영상 생성은 계산력(FLOPS)이 병목이다. [p14#lv4]
